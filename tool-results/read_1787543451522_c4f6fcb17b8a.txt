   718→   718→        <h2>What is Liquid Glass?</h2>
   719→   719→        <p>
   720→   720→                Liquid Glass is a lightweight JavaScript/TypeScript library that applies realistic glass refraction, blur, chromatic aberration, and lighting effects to any HTML element using WebGL shaders. It captures the DOM content behind each glass element, processes it through a multi-pass rendering pipeline, and composites the result in real time.
   721→   721→        </p>
   722→   722→        <p>
   723→   723→                The library handles layered compositing (glass-on-glass), dynamic content updates, draggable floating panels, responsive resizing, and works with any background &mdash; images, videos, canvases, or plain HTML.
   724→   724→        </p>
   725→   725→
   726→   726→        <h2>Getting Started</h2>
   727→   727→        <p>Install via npm:</p>
   728→   728→        <pre class="language-bash"><code>npm install @ybouane/liquidglass</code></pre>
   729→   729→
   730→   730→        <p>Or skip the install and import directly from a CDN:</p>
   731→   731→        <pre class="language-javascript"><code>import { LiquidGlass } from 'https://cdn.jsdelivr.net/npm/@ybouane/liquidglass/dist/index.js';</code></pre>
   732→   732→
   733→   733→        <p>Basic usage:</p>
   734→   734→        <pre class="language-javascript"><code>import { LiquidGlass } from '@ybouane/liquidglass';
   735→   735→
   736→   736→const instance = await LiquidGlass.init({
   737→   737→    root: document.querySelector('#my-root'),
   738→   738→    glassElements: document.querySelectorAll('.glass'),
   739→   739→});
   740→   740→
   741→   741→// Later:
   742→   742→instance.destroy();</code></pre>
   743→   743→
   744→   744→        <p>The root element must be a positioned container (<code>position: relative</code>) and each glass element must be a direct child of the root. Each glass element gets a child <code>&lt;canvas&gt;</code> injected automatically for the shader output.</p>

   849→   849→<div class="section">
   850→   850→        <h2>Limitations &amp; Gotchas</h2>
   851→   851→        <p>
   852→   852→                The library leans on real-time DOM rasterisation and a multi-pass WebGL pipeline. That comes with a handful of constraints worth knowing before you wire it into a production page.
   853→   853→        </p>
   854→   854→
   855→   855→        <h3>Structural</h3>
   856→   856→        <ul>
   857→   857→                <li><strong>Glass elements must be direct children of the root.</strong> Nested glass is rejected at init with a console warning. If you need glass inside a wrapper, give the wrapper its own <code>LiquidGlass.init()</code> call.</li>
   858→   858→                <li><strong>The root itself is never captured.</strong> The shader samples the root's <em>children</em>, so any background image, padding, or border on the root is invisible to the glass effect. Put backgrounds in a sibling element <em>inside</em> the root (e.g. an absolutely positioned <code>&lt;img&gt;</code>).</li>
   859→   859→                <li><strong>A <code>&lt;canvas&gt;</code> is injected as the glass element's first child</strong> for shader output. Avoid <code>:first-child</code> selectors on glass elements.</li>
   860→   860→                <li><strong>Multiple LiquidGlass roots cannot share refraction.</strong> A glass element in one root cannot see what another root's glass elements are rendering — they each have their own compositing canvas.</li>
   861→   861→        </ul>
   862→   862→
   863→   863→        <h3>Performance</h3>
   864→   864→        <ul>
   865→   865→                <li><strong>Capturing DOM into a canvas is expensive.</strong> Every non-glass wrapper is rasterised via <code>html-to-image</code> (style inlining + SVG-foreignObject decode). Keep wrappers small and shallow.</li>
   866→   866→                <li><strong><code>data-dynamic</code> elements are treated as always dirty by definition.</strong> Use it only for content that genuinely changes every frame — animations, counters, charts. For one-shot updates, prefer <code>instance.markChanged()</code> instead — it costs nothing on idle frames.</li>
   867→   867→                <li><strong>Each LiquidGlass instance opens its own WebGL context.</strong> Browsers cap concurrent contexts (typically 16 system-wide); don't spawn dozens.</li>
   868→   868→                <li><strong>Window resize re-captures everything.</strong> Don't drive layout in a tight resize loop.</li>
   869→   869→        </ul>
   870→   870→
   871→   871→        <h3>Text &amp; fonts</h3>
   872→   872→        <ul>
   873→   873→                <li><strong>Webfonts must be loaded before <code>init()</code></strong> and served with CORS-friendly headers. Google Fonts, jsdelivr, and unpkg work out of the box. Call <code>invalidateFontEmbedCache()</code> then re-init if you load fonts dynamically.</li>
   874→   874→                <li><strong>Cross-origin <code>&lt;img&gt;</code> elements need <code>crossorigin="anonymous"</code></strong>. Tainted canvases break texture upload and disable the glass effect for the entire root.</li>
   875→   875→        </ul>
   876→   876→
   877→   877→        <h3>API</h3>
   878→   878→        <ul>
   879→   879→                <li><strong><code>LiquidGlass.init()</code> is async</strong> — it resolves only after font CSS prefetch, glass content pre-capture, and static-content pre-warm have all completed. On a slow connection that can be 100&ndash;500&nbsp;ms.</li>
   880→   880→                <li><strong><code>data-dynamic</code> only catches direct children of the root.</strong> A live element nested inside a wrapper that lacks <code>data-dynamic</code> will not trigger re-captures.</li>
   881→   881→                <li><strong>The library auto-detects <code>&lt;video&gt;</code> elements as dynamic</strong> &mdash; you don't need to add <code>data-dynamic</code> to them.</li>
   882→   882→                <li><strong><code>instance.markChanged(element)</code></strong> &mdash; call after updating something the library can't observe on its own (a <code>&lt;canvas&gt;</code> you just painted, an <code>&lt;img&gt;</code> you swapped, a CSS property you toggled). Only glasses overlapping that element re-render. Call with no argument to invalidate everything.</li>
   883→   883→                <li><strong><code>invalidateFontEmbedCache()</code></strong> &mdash; call after dynamically loading new font stylesheets so the next <code>init()</code> rebuilds the embedded font cache.</li>
   884→   884→        </ul>
   885→   885→</div>
